# 职业健康档案系统（OHAS）

**当前版本：1.0.0beta**　**库结构版本：21**

OHAS 是面向用人单位的职业健康档案管理系统。系统以《职业卫生档案管理规范》六类档案为主线，以劳动者个人职业健康监护档案（表6-1）为核心，通过「作业场所 → 岗位 → 危害因素配置」组织基础数据，自动把检测结果、体检记录、职业病诊断、培训与防护用品记录归集到个人档案，并提供资料归档自查、表样打印与到期提醒。

系统定位是**档案库与资料归档助手**：负责把资料收齐、挂对、找得到、能打印；不做风险分级、不给评分、不换算百分比，也不替代职业病诊断机构的专业结论。

## 二、技术栈与运行环境

- PHP 8.1+；必需扩展：`pdo_sqlite`、`fileinfo`、`mbstring`；建议启用 `gd` 用于照片压缩。
- SQLite 3 单文件数据库；零外部服务、无 Composer、无前端 CDN。
- 自研轻量 MVC：单入口路由、Core/Controllers/Models/Helpers/Views 分层。
- 界面基于本地化的 Tabler UI / Bootstrap 5，内网部署无需访问外部地址。
- 浏览器：Chrome / Edge 等现代浏览器；打印依赖浏览器打印能力。

## 三、部署与安装

### 3.1 便携包（Windows）

运行 `start.ps1`，浏览器访问 `http://127.0.0.1:8080/`。首次访问进入安装向导。

### 3.2 Web 服务器

站点根目录推荐指向 `public/`；指向应用根或子目录也可，入口会自动计算链接前缀。

- phpStudy / Apache：创建站点，选择 PHP 8.1+，勾选扩展，访问站点进入安装向导。
- 宝塔 / nginx：站点根指向 `public/`；若未透传 PATH_INFO，将 `config.php` 中 `app.url_mode` 改为 `'query'`。
- `storage/` 必须由 PHP 进程可写。

URL 模式：

| 模式 | 链接形态 | 适用场景 |
|---|---|---|
| `path`（默认） | `index.php/workers/edit?id=5` | Apache / phpStudy |
| `query` | `index.php?r=workers/edit&id=5` | nginx 未配置 PATH_INFO |

### 3.3 安装向导写入内容

1. 执行 `database/schema.sql` 建库；
2. 创建管理员（密码 bcrypt 哈希）；
3. 写入单位名称；
4. 默认同步《职业病危害因素分类目录》459 条：

| 类别 | 条数 |
|---|---:|
| 粉尘 | 52 |
| 化学因素 | 375 |
| 物理因素 | 15 |
| 放射性因素 | 8 |
| 生物因素 | 6 |
| 其他因素 | 3 |

其中 339 条附现行标准接触限值，151 条预填可能职业病。目录数据可在系统中增删改，后续点「同步目录」只补充/校正法定目录内容，不覆盖用户自行维护的状态与备注。

安装结束写入 `storage/installed.lock`，其内容包含应用版本与库结构版本；库结构版本唯一来源为 `Migrator::VERSION`。

### 3.4 安装后检查

- `storage/ohas.db` 与 `storage/installed.lock` 已生成；
- 使用 `admin` 与安装时设置的密码登录；
- 工作台「数据准备向导」显示单位信息已完成。

## 四、数据主线

```text
company（单行）
  └→ 表2-2；事故报告页眉预填

workplaces ─1:n─ posts ─1:n─ post_hazards ─n:1─ hazards
                    └→ 表4-2；岗位危害配置；接害判定依据

workers ─1:n─ worker_posts / worker_illnesses / diseases
        ├─1:n─ exam_records ─n:1─ exam_batches
        ├─1:n─ ppe_issues
        └─n:n─ trainings（经 training_participants）
  └→ 表6-1、表5-1~5-4、表6-3

detection_reports ─1:n─ detection_items ─n:1─ workplaces / posts / hazards
  └→ 按「岗位 + 检测日期落入接害区间」归集到劳动者
  └→ 表6-2、表4-3、检测年度视图

documents（link_type + link_id 多态关联）
  └→ 原件唯一存放处；删除业务记录时触发器解除关联，原件保留
  └→ 个人资料矩阵 / 单位资料清单 / 到期提醒
```

有意保留的冗余：

- `worker_posts.hazards_snapshot / protection_snapshot`：职业史结束段冻结当时快照，后续改岗位配置不改写历史。
- `exam_records.post_name / hazards_snapshot`：体检受检时岗位与危害快照，按检查日期取值。
- `detection_items.workplace_id` 与 `post_id` 并存：未指定岗位时按场所归集；指定岗位时自动带出场所。
- `detection_items.matched_post_ids`：检测明细保存时冻结可归集岗位，后续危害配置变化不漂移历史归集。

## 五、核心业务口径

### 5.1 接害判定

全系统统一由 `Exposure` 判定。当前接害 = 在职 + 在岗职业史段 + 岗位启用 + 岗位有危害配置。工作台、表2-2、表4-2 使用同一口径。

接害工龄按职业史区间并集计算，兼岗与重叠录入不会重复累加。已结束段冻结历史快照，历史接害不会因后来修改岗位危害配置而消失。

状态变为离职/离岗/退休时必须填离岗日期，系统在同一事务内收尾所有未结束职业史段；新增“至今”职业史段时默认把上一段收尾至新开始日前一天，兼岗可取消该选项。

### 5.2 体检结论与处置闭环

异常口径：已出结论且不是「目前未见异常/未见异常」；包括「其他疾病或异常」，与表5-2 一致。

闭环前置条件按以下顺序判定：

1. 疑似职业病/职业病须生成表5-3/5-4 登记；
2. 必须填写人员处理情况；
3. 告知方式必须为书面签收，电话/当面/其他不算闭环；
4. 必须挂「体检结果书面告知/签收」原件；
5. 必须有本人签字确认日期；
6. 职业禁忌证须结束接害在岗段或挂调岗通知书。

异常列表提供待登记、待处置、待告知、非书面告知、待告知原件、待调离、已闭环七类筛选；工作台卡片与列表同年同口径。

### 5.3 检测数据

- 检测报告日期必填且不得晚于今天；报告日期不得早于检测日期。
- 检测明细须选择危害因素，并至少关联场所或岗位；岗位与场所不一致时自动对齐岗位所属场所。
- 采样类型区分 TWA / STEL / MAC / 峰，避免把短时结果与时间加权限值错配。
- 已填检测结果或接触限值必须选择判定结论；未判定明细单独统计，不冒充合格。
- 合格率剔除未判定检测点；有超标时最高显示 99%，不把 199/200 显示成 100%。
- 停用仍有在岗人员的岗位、停用仍被引用的危害因素时给出明确提示。

### 5.4 档案与线索

- 事件线索按「异常年份 ≤ 材料年份」匹配：旧调岗通知不能永久覆盖后来新出现的职业禁忌证。
- 线索包括：禁忌证调岗、复查材料、疑似职业病诊断材料、确诊职业病诊断证明、离岗档案复印件签收。
- 非在职且有接害史的人员缺 `W_COPY_SIGN` 时进入线索；表5-6 归集复印件提供与签字状态。
- 新增接害岗位段若无同年度或更晚的危害告知书，个人资料页给出重新告知提示。
- 不适用白名单仅允许自评表规定有合理缺项的项（C01/C02、C16–C18、C23），原因必填。

### 5.5 删除与保管

- 体检记录与职业病登记属于长期监护档案：劳动者名下有两类记录时禁止物理删除，应改为离职/离岗/退休。
- 删除普通劳动者时，确认弹窗列明职业史、既往病史、参训记录、劳保领用记录与文档解除关联数量。
- 体检记录与职业病登记一一对应；删除体检记录时登记保留并解除来源关联。
- 检测报告被整改台账引用时不可删除，须先解除引用。

## 七、日常使用流程

### 7.1 数据准备

1. 录入单位信息；
2. 核对危害因素字典，停用本单位不涉及的因素；
3. 建立作业场所 → 岗位 → 岗位危害配置；
4. 劳动者建档：手工录入或 CSV 批量导入；
5. 维护职业史，本单位岗位自动带出危害与防护快照。

CSV 导入以身份证号唯一识别，支持 UTF-8/GBK，先预览后写入，单次上限 1000 行；非在职人员必须填写离岗日期。

### 7.2 检测登记

1. 登记检测报告并上传原件；
2. 录入检测明细：场所/岗位、危害因素、检测点、结果、单位、限值、采样类型、判定；
3. 系统按保存时岗位快照归集到劳动者表6-2；
4. 在信息卡查看页或检测结果查询页按人打印表6-2；
5. 超标点可一键生成整改草稿并挂复测资料。

### 7.3 体检登记

1. 登记体检批次，填写检查日期、种类、机构、应检人数；
2. 从应检名单生成待检记录；离职后补做离岗体检/随访/诊断/复查仍可选择对应人员；
3. 逐人登记结论、处理情况、告知方式、告知书原件与签字日期；
4. 疑似职业病/职业病一键生成表5-3/5-4 登记；
5. 职业禁忌证须完成调离取证后闭环；
6. 在信息卡查看体检时间线，按人打印表6-3。

### 7.4 资料归档

1. 用 `documents/quick` 批量上传原件，选择资料类型与所属年度；
2. 顶栏搜索劳动者进入「一人一档」全景页，查看年度矩阵、一次性资料、事件类与其他资料；
3. 侧栏「资料清单」查看单位 36 项状态、缺失名单、CSV 导出与 A4 打印；
4. 需要说明缺项原因时标记不适用；
5. 工作台查看到期资料、异常闭环与线索人员名单。

## 八、备份、升级与安全

### 8.1 备份

- 系统内备份：系统管理 → 数据备份 → 立即备份，生成包含 `ohas.db` 与 `uploads/` 的 zip；
- 手工备份：复制 `storage/ohas.db` 与 `storage/uploads/`；
- 恢复：停止站点 → 覆盖数据库与上传目录 → 重启验证；
- 建议每周备份一次，批量导入、归档或升级前后追加备份。

### 8.2 升级

用新版文件覆盖除 `storage/` 外的目录，首次访问自动执行 `Migrator` 迁移。迁移前自动备份数据库：`user_version` 记录当前结构版本，所有步骤幂等。新装库执行 `schema.sql` 后直接写入相同版本，结构一致性由自测校验。

### 8.3 安全

- 密码 bcrypt 哈希；单账号连续 5 次失败锁定 5 分钟；闲置 2 小时登出。
- PDO 预处理防 SQL 注入；模板统一输出转义防 XSS；POST 表单 CSRF 校验。
- 上传白名单 + MIME 复核 + 随机重命名，文件存于 Web 根之外。
- 操作日志记录登录、登出、增删改与导入。
- `storage/`、`app/`、`database/`、`tools/`、`docs/` 自带目录保护；nginx 需自行配置拒绝规则。
- `tools/*.php` 仅限命令行或开发服务器执行，Web 访问返回 403。

## 十、标准依据与边界

标准依据：

- 《职业卫生档案管理规范》六类档案及表样；
- GBZ 188-2025《职业健康监护技术规范》（检查种类与结论口径）；
- GBZ 2.1-2019 及修改单、GBZ 2.2-2007（接触限值）；
- GB 18871（电离辐射相关限值）；
- 《职业病危害因素分类目录》（国卫疾控发〔2015〕92号）；
- 《职业病分类和目录》（2024版）；
- 《用人单位职业健康信息系统基本功能标准》WS/T 880—2025（摘录见 `docs/WST880-2025-摘录.txt`）。

当前边界：

- 不做评分、分级、风险评价与百分比完整度；
- 不提供 OCR 或自动拆分匹配资料；
- 不按个人实际接触水平/作业分级自动推断体检周期提醒；
- 内置接触限值与可能职业病为预填参考，最终以现行有效标准文本和职业病诊断机构结论为准。
