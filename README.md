# OHAS — 职业健康档案管理系统

OHAS（Occupational Health Archive System）是一套面向用人单位的职业健康档案管理系统，以《职业卫生档案管理规范》的六类档案为主线，以劳动者个人职业健康监护档案为核心。

系统围绕「作业场所 → 岗位 → 职业病危害因素 → 劳动者接害记录」组织数据，将检测、体检、职业病诊断、培训、防护用品、分类文档和辅助台账归集到单位档案及个人档案中，并提供资料缺口检查、到期提醒、表样打印和资料包导出。

**当前版本：** `1.0.0beta`  
**数据库结构版本：** `21`

## 核心能力

- **基础信息与接害配置**
  - 单位信息、作业场所、岗位、危害因素字典
  - 岗位与危害因素关联，保存历史接害快照
  - 内置法定职业病危害因素目录及接触限值参考

- **劳动者档案**
  - 身份证校验、档案号生成、职业史、既往病史和职业病诊断
  - 照片、文档上传、个人全景资料矩阵
  - CSV 批量导入，导入前支持预览

- **工作场所检测**
  - 检测报告、检测明细、采样类型和判定结果
  - 按岗位接害区间归集检测数据
  - 检测年度视图、超标点统计及整改台账

- **职业健康体检**
  - 体检批次、应检名单、逐人检查记录
  - 异常处置、书面告知、职业禁忌证和调岗闭环
  - 疑似职业病/职业病登记联动及个人体检时间线

- **资料归档与台账**
  - 单位资料清单、个人年度资料矩阵和缺失/不适用标记
  - 三同时、培训、防护设施、应急演练、事故报告等辅助台账
  - 分类文档上传、有效期、重命名、资料导出和到期提醒

- **表样打印**
  - 职业卫生档案规范表样及系统扩充表样
  - 一人一卡、台账整表、自动补空行及 A4 打印版式

## 技术栈

| 项目 | 说明 |
|---|---|
| 运行环境 | PHP 8.1+ |
| 数据库 | SQLite 3 |
| 架构 | 自研轻量 MVC，单入口路由 |
| 前端 | 本地 Tabler UI / Bootstrap 5、原生 JavaScript |
| 部署方式 | Windows 便携包、Apache、Nginx、phpStudy、宝塔等 |
| 必需 PHP 扩展 | `pdo_sqlite`、`fileinfo`、`mbstring` |
| 可选 PHP 扩展 | `gd`（照片压缩） |

项目不依赖 Composer、外部数据库或前端 CDN，适合内网部署。

## Windows 便携运行

Windows 10/11 64 位环境下：

1. 解压 `OHAS.zip` 或进入 `OHAS/` 目录。
2. 双击 `start.bat`，或在 PowerShell 中运行：

   ```powershell
   .\OHAS\start.ps1
   ```

3. 浏览器访问 `http://127.0.0.1:8080/`。
4. 首次访问会进入安装向导，创建管理员账号并填写单位信息。

便携服务配置位于 `OHAS/fennec.ini`：

- 默认监听端口：`8080`
- 默认仅监听本机：`127.0.0.1`
- 默认站点根目录：`./wwwroot/public`
- 默认需要的 PHP 目录：`./../../php-8.6`
- 可按需修改端口、局域网监听和线程配置

局域网访问时，将 `fennec.ini` 中的 `lan = 0` 改为 `lan = 1`，重启便携服务，并确保防火墙允许端口访问。

## Web 服务器部署

应用根目录为 `OHAS/wwwroot`。

### Apache / phpStudy

- 站点根目录可指向 `OHAS/wwwroot/public`
- PHP 版本选择 8.1 或更高
- 启用 `pdo_sqlite`、`fileinfo`、`mbstring`；建议启用 `gd`
- 配置保留默认的 `path` URL 模式
- 首次访问站点时进入安装向导

也可将站点根目录指向 `OHAS/wwwroot`。根目录入口会兼容子目录部署并自动计算资源和页面链接。

### Nginx / 宝塔

- 推荐将站点根目录指向 `OHAS/wwwroot/public`
- 确保 PHP-FPM 能访问并写入 `storage/`
- 若反向代理未透传 `PATH_INFO`，将 `OHAS/wwwroot/config.php` 中的：

  ```php
  'url_mode' => 'path',
  ```

  改为：

  ```php
  'url_mode' => 'query',
  ```

链接格式将由 `/index.php/workers/edit` 切换为 `/index.php?r=workers/edit`。

### 直接使用 PHP 开发服务器

```bash
cd OHAS/wwwroot
php tools/dev_init.php
php -S 127.0.0.1:8099 tools/dev-server.php
```

随后访问 `http://127.0.0.1:8099/index.php/auth/login`。开发种子管理员账号为 `admin`，密码为 `admin12345`。

## 首次安装

安装向导会完成以下操作：

1. 执行 `OHAS/wwwroot/database/schema.sql` 初始化数据库。
2. 创建管理员账号，密码使用 bcrypt 存储。
3. 写入单位名称及单位信息。
4. 同步职业病危害因素目录。
5. 在 `storage/` 中生成 `ohas.db` 和 `installed.lock`。

安装后需确认：

- `OHAS/wwwroot/storage/ohas.db` 已生成
- `OHAS/wwwroot/storage/installed.lock` 已生成
- `storage/` 可由 PHP 进程读写
- 管理员可正常登录工作台

数据库可以通过 `OHAS_DB` 环境变量覆盖，例如：

```bash
OHAS_DB=/tmp/ohas-test.db php tools/selftest.php all
```

## 主要业务口径

- 接害判定以在职状态、在岗职业史区间、岗位启用状态和岗位危害配置为依据。
- 接害工龄按职业史区间的并集计算，兼岗重叠不会重复累加。
- 岗位及体检记录保存关键历史快照，后续岗位配置变化不改变既往归集结果。
- 检测明细保存时冻结可归集岗位；采样类型区分 TWA、STEL、MAC 和峰值。
- 异常体检结论需按处置、告知、原件和签字状态完成闭环。
- 职业禁忌证须完成调离取证或挂调岗通知后才能闭环。
- 离职、离岗、退休人员或长期监护档案使用受控状态收尾，不随意删除。

## 备份与升级

### 系统内备份

进入「系统管理 → 数据备份」，可将 SQLite 数据库和上传文件打包为 ZIP。

可通过自动备份保留数据库及上传原件；建议在批量导入、资料归档和升级前后执行备份。

### 手工备份

至少备份：

- `OHAS/wwwroot/storage/ohas.db`
- `OHAS/wwwroot/storage/uploads/`

恢复时应先停止站点，再覆盖数据库和上传目录，最后重启并验证登录及数据。

### 升级

用新版文件覆盖项目目录中除 `storage/` 外的内容。首次访问时，`Migrator` 会根据数据库的 `user_version` 执行幂等迁移，并在迁移前备份数据库。

不要直接复制或删除正式数据库，升级前应保留完整备份。

## 安全说明

- 密码使用 bcrypt 哈希存储。
- 连续 5 次登录失败后锁定 5 分钟。
- 配置的闲置时长为 2 小时。
- 全部数据库查询优先使用 PDO 预处理。
- 模板统一转义输出，降低 XSS 风险。
- POST 操作校验 CSRF 令牌。
- 上传文件采用扩展名、MIME 和随机重命名策略。
- 上传原件保存于 `storage/`，不直接暴露在公开站点中。
- 操作日志记录登录、登出、增删改和导入行为。
- `storage/`、`app/`、`database/`、`tools/` 和 `docs/` 已包含目录保护；使用 Nginx 时仍应补充拒绝规则。

## 标准依据与适用边界

主要依据包括：

- 《职业卫生档案管理规范》及六类档案表样
- GBZ 188-2025《职业健康监护技术规范》
- GBZ 2.1-2019 及其修改单、GBZ 2.2-2007
- GB 18871 电离辐射相关限值
- 《职业病危害因素分类目录》
- 《职业病分类和目录》（2024 版）
- 《用人单位职业健康信息系统基本功能标准》WS/T 880—2025

系统定位为档案管理、资料归集和归档助手，不替代职业病诊断机构，不提供风险分级、风险评分或自动百分比判定。内置接触限值和可能职业病信息只作为参考，最终应以现行有效标准和专业诊断结论为准。
